# Operations demo controls and health

## Outcome and scope

An explicitly authorised demo operator can pause/resume one simulated train, simulate/restore Grilled availability and see dependency/backlog recovery without exposing internal credentials. This is a small light Operations panel, not a replacement Aspire dashboard. Follow [handoff 9](../docs/app-spec-plan.md#9-operations-demo-controls-and-health--copy-this-prompt), [operations workspace](operations-workspace.md), [running backend](simulated-running.md), [Grilled T6](grilled.md), [local setup/drill](../services/README.md) and [app foundation](app-foundation.md).

## Current code and ownership

- `Rail/Running/SimulatorSetup.cs` supplies service-key-protected POST `/internal/rail/simulator/journeys/{id}/pause` and `/resume`, with in-memory `SimulatorControl`. `Program.cs` maps them only in Development. `Simulator:Enabled` controls the worker; a paused flag is not evidence freshness or proof the train stopped physically.
- Access has `simulation.control`, seeded only for SimOperator. There are no browser-safe signed-in control routes in the inspected mappings. Never send `X-SmartRail-Service-Key` or any provider key from React, a VITE variable, URL or browser storage.
- Grilled `dev-controls.ts`/`server.ts` has GET/PUT `/internal/dev/outage`, guarded by its service key and enabled only for local non-production drills. PUT takes `{active: boolean}`; restore and health remain reachable during outage. The switch is memory state, not durable provider availability.
- `CateringHealthCheck.cs` and `Infrastructure/HealthResponseWriter.cs` expose readiness, provider state and counts/ages: `outboxPending`, `outboxFailed`, `oldestOutboxSeconds`, `ordersPending`, `oldestPendingOrderSeconds`. Provider failure degrades food dependency without breaking public train reads or liveness. Do not interpret an unavailable count as zero.
- `services/apphost/AppHost.cs` already wires separate keys, service addresses and a file-backed SQLite path. `DrillApiTests.cs` and `FeatureAcceptanceApiTests.cs` exist. Grilled T6 is checked, but its final evidence paragraph still says the local drill/AppHost/hosted CI have not been verified. Recheck and reconcile that evidence in its owning task; do not build duplicate workers, telemetry or recovery tests here.
- Seed source has fixed train times/configurable dates, not a presentation-anchor command. [Pilot acceptance](pilot-app-acceptance.md) owns the minimal repeatable presentation-relative fixture. This panel selects known dated IDs; it does not edit the timetable, shift browser clocks or invent in-service trains.

## Demo permissions — user confirmed

SimOperator can use **all Development-only demo controls and diagnostics**. Use the existing network-scoped `simulation.control` permission for train pause/resume, simulated provider outage/restore and the panel's diagnostic read. Other accounts need an explicit grant of that permission; Controller/SysAdmin status or `accounts.manage` alone grants none. No additional provider/health permission codes or automatic SysAdmin grant are needed for this panel.

Recheck active account, permission and grant expiry on every adapter request. This decision does not grant operational train-change authority or relax Development-only gating. Existing anonymous health endpoints retain their existing public contract; the new staff panel/adapter uses the selected policy.

## Server adapter and UI

Add small authenticated routes under `/api/demo`: read selected journey simulation state, POST its pause/resume, GET/PUT provider outage, and read sanitised dependency/backlog diagnostics. Enforce `simulation.control` on the server, active account and Development-only availability; train simulation actions also require `Simulator:Enabled`. Do not let client parameters choose an arbitrary upstream host or command. Rail actions use the existing control/ticker services; provider actions use a fixed configured server-side client with its existing service credential. Add successful/denied action audit entries without secrets/payloads. State-changing calls are idempotent assignments of desired state, not toggles.

The provider adapter's restore action must remain reachable during the simulated outage; do not gate it on provider readiness. Distinguish an actual stopped process (cannot restore with an HTTP switch; direct the operator to Aspire) from a simulated outage. Missing config, non-demo environment, denied access, provider timeout and unknown state have honest responses. Never display success before confirmation; after a lost response reread desired/actual control state before allowing a retry.

The panel shows simulation Enabled/Paused/Running separately from observation CURRENT/AGEING/UNKNOWN and provider Healthy/Degraded/Unavailable/Unknown. Show last checked time, backlog counts/oldest ages and permanent failure count. Poll every 15 seconds while visible, refresh after actions/resume and prevent overlapping requests. A failed read keeps last values clearly historical. Link configured local trace/dashboard URLs without credentials; do not embed or recreate the dashboard. No provider cutoff editor is added here; its owner-controlled CLI/API drill remains in Grilled T6.

## Evidence (T1 implemented 2026-10-18)

**T1 — done.** The adapter is `services/api/Modules/Demo/DemoSetup.cs`, registered by `AddSmartRailDemo`/`MapDemoEndpoints` and mapped only in Development (`Program.cs`). Every route needs the network-scoped `simulation.control` permission, rechecked from the database on each call: `GET /api/demo/journeys/{journeyId}/simulation`, `POST .../pause`, `POST .../resume`, `GET`/`PUT /api/demo/provider/outage`, and `GET /api/demo/diagnostics`. Pause/resume change the in-process `SimulatorControl` directly, never this API's service-key internal route. The provider switch is a new pair of methods on the existing `IGrilledClient`, so it uses the fixed server-side address and its existing service credential; the browser sends no key. Each action is an idempotent assignment of desired state (`pause`/`resume`, or `{active}`) and writes a `SUCCEEDED` audit row; a denied request is audited by the existing policy handler. Diagnostics reuse the same `CateringHealthCheck` as `/health/ready` (counts and ages only). One implementation choice not fixed by the spec: a pause/resume while `Simulator:Enabled` is false answers `409` with code `SIMULATOR_DISABLED` and changes nothing; an unreachable provider answers `503 PROVIDER_UNAVAILABLE` with the "start it from Aspire" wording.

Passed: `dotnet build services/api` (0 errors); `dotnet test tests/SmartRail.Api.Tests` with `SMARTRAIL_TEST_POSTGRES`, **456 of 456 tests** (3m03s), including 10 new in `tests/SmartRail.Api.Tests/Demo/DemoControlsApiTests.cs`. The new checks cover: SimOperator allowed and idempotent pause/resume with audit rows; an explicit `SIM_OPERATOR` grant opening a Controller account while ungranted Controller/SysAdmin and a guest are refused (denial audited); expired and revoked grants refused; unknown journey `404`; disabled simulator `409` with state unchanged and still readable; `/api/demo` absent in a Production host; the outage switch setting and ending a real Grilled outage with its own route staying reachable while the provider answers `503`; diagnostics returning the readiness numbers; and no observation, callback, admin or kiosk secret in any response. Checks not run: T2–T4 (blocked above). The web build/lint and Flutter checks are not relevant to this backend-only task and were not run.
