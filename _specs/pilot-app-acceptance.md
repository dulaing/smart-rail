## Cross-cutting acceptance

- Two editors produce one committed write and one `STALE_PREVIEW` 409; the loser needs new review. A lost write response reconciles with server state without an automatic second publish.
- Wrong station, wrong assigned journey, another passenger's saved route/follow/order and another kiosk's actions are denied server-side. Controller cannot read Auditor-only history; SysAdmin cannot write train changes. Public train/board reads work while Keycloak is unavailable.
- Logout/account switch/cache isolation, pending order restart/retry, driver same-key report retry and unfollow response races are verified. **User-confirmed driver policy:** after prior sign-in/download, offline restart with failed token refresh may show the same owner's saved briefing read-only with age; no server actions, and logout/account switch/definitive online rejection locks/clears it. **User-confirmed personal alerts:** current effective changes only; withdrawals remove items, with no unread badges or notification history.
- **User-confirmed staff boundaries:** RailBites uses one shared human staff login per collection point and a server session; internal keys never reach browser code/storage. SimOperator's `simulation.control` permits all Development-only demo controls/diagnostics; other accounts need an explicit grant. Test both permitted sessions and cross-point/ungranted-role refusals.
- Real provider outage/restore produces a backlog, leaves trains readable, drains on recovery and survives service restarts with durable data. Provider cutoff changes without SmartRail release. Reuse RailBites T6's owning evidence, adding only missing connected-screen assertions.
- Build/lint/analysis and focused tests for all apps, keyboard/NVDA where applicable, TalkBack, 200% text, contrast/touch targets, long Sinhala/Tamil and actual native-reader review. A physical four-metre board check needs real observation. Unavailable people/devices are precise pending checks, not passes.

## Evidence (T1 implemented 2026-10-18)

**T1 — done.** `dotnet run --project services/api -- --seed-demo --anchor <offset-bearing ISO time>` (Development only) reuses `DatabaseSetup.SeedAsync` with the anchor's Colombo service date, then builds a manifest from the seeded rows and writes it to `artifacts/pilot-scenario-<run>.json` (override with `--manifest`/`--run`) while printing the same IDs. It adds only missing journeys and never resets versions, so a repeat run is idempotent; both directions are present and `SIM-3001` has Polgahawela before Peradeniya with Peradeniya marked unserved after an early end at Polgahawela. The manifest lists dated journey/stop/station IDs, routes, times, the intended demo identities and the two RailBites collection points, and carries no credentials.

Checks actually run: `dotnet build services/api/SmartRail.Api.csproj` succeeded (one pre-existing duplicate-using warning). `dotnet test tests/SmartRail.Api.Tests --filter FullyQualifiedName~PilotScenario` passed 12/12 with `SMARTRAIL_TEST_POSTGRES` set (anchor offset/service-date mapping, anchor without an offset rejected, both routes and stop order, repeat seeding without new journeys or a reset version, no-credential manifest, manifest file written). The full suite passed 458/458 when run with test collections not parallelised; the default parallel run failed with Npgsql 53300 "too many clients already" against the shared PostgreSQL, an environment connection limit rather than a code failure, so it was rerun sequentially. `dotnet run --project services/api -- --seed-demo` with no anchor printed the required-offset message and exited 2 without touching the database.

Not run: the CLI happy path against a live database (creating a disposable database needs the test harness; the same seed-and-manifest code is covered by the database tests), and any real-stack rehearsal (T4).

RailBites T6's own spec still says its operator drill, AppHost secret/address wiring and hosted CI are unverified, so this work does not claim that drill passed; its owner must reconcile the checked box with that paragraph.

**T2, T3, T4 — blocked, not started** for the reasons in their task lines above.
